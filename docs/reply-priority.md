# 返信待ちを確認し、AIで並べる

[READMEへ戻る](../README.md)

返信待ちとJev判定を開発版に復元しています。実Jevの日本語品質試験は基準未達で、一部の実画面試験も残っています。[残る検証](roadmap.md)を確認してください。

## DMと直接メンションから返信待ちを探す

1. Slack Hubを開き、右上の表示切替で「返信待ち」を選びます。
2. 既定は過去24時間です。Actionsの「過去7日」で期間を変えられます。
3. 行を選び、ReturnでSlackを開きます。⌘Returnで取得した会話を最新の投稿から確認できます。
4. 「確認待ち」がある場合は、Actionsの「続きを確認」で残りの履歴を取得します。⌘Rは新しく取り直します。

対象は1対1 DMと、自分への直接メンションです。グループDMは直接メンションだけを対象にします。`@here`・`@channel`・ユーザーグループ宛ては含めません。

同じ会話で対象投稿より後に自分の投稿があるかを確認します。以前に返信していても、その後の新しい依頼は候補に戻ります。履歴を取得しきれない場合は確認待ちに残します。Slackを開いた操作や既読、リアクションだけでは候補を除きません。

AIを使わない一覧では、履歴を確認した「未返信候補」を先に表示し、取得不足などの「要確認」をその下に表示します。未返信候補でも、返信が必要かは本文を確認して判断します。

## 範囲と投稿者を絞る

Actionsの「検索条件を選ぶ」で、お気に入りチャンネル・セクション・チャンネルと投稿者を指定できます。Hubで選んだ条件も引き継ぎます。チャンネルを限定するとDMは対象外です。「すべて」で投稿者だけを指定すると、その人からのDMと直接メンションを探します。

投稿者を絞っても、返信済みかの確認とAIに渡す会話には他の人の投稿を含めます。条件を変更するだけではAIへ送りません。再び手動判定を選び、対象を確認して同意してください。[検索範囲の選び方](search-scopes.md)も参照できます。

## 返信・除外・延期を使う

- 返信する場合は、行のActionsで「Reply in Thread」を選びます。フォームを開く前に履歴を再確認します。送信成功後に取り直し、後続の自分の投稿が確認できたら候補から外します。送信失敗時は残します。
- 返信しなくてよい候補は「返信不要」で除外できます。
- 「あとで対応・1時間」「あとで対応・翌朝9時」で延期できます。翌朝9時は利用者のタイムゾーンで計算します。
- 表示切替の「除外・あとで対応」から取り消せます。新しい依頼が来たら以前の除外・延期は適用しません。

## Jevで優先候補を並べる

1. Raycastの設定→Extensions→Slack Hubで、任意の「TypeSafe API Key」を設定します。キーはチャットやGitHubに貼らないでください。
2. 返信待ちのActionsから「AIで並べる・再試行」を選びます。
3. 送信先と対象を確認し、同意した場合だけ判定を始めます。
4. 判定が終わったら「AI判定を反映」を選びます。判定中に行の順序は変えません。

返信の必要性、期限の切迫、返答待ちによる業務停止、催促を判定します。「要確認」「優先候補」「返信不要の可能性」に分け、期限と業務停止の程度で優先候補を並べます。AIの判断だけでは候補を隠しません。

TypeSafeへ会話本文・投稿時刻・タイムゾーン・相対化した投稿者情報を送ります。Slackトークンやプロフィールは送りませんが、本文に書かれた名前やメールアドレスなどは自動では除去しません。ファイルの中身やリンク先は取得しません。

1回は最大20候補、同時2件です。1候補は最大30投稿・送信データ16,000文字までに制限します。途中の省略や曖昧な判定は要確認に残します。TypeSafeの利用料金が発生します。Claude Codeのサブスクリプションは使いません。

設定・開き直し・キャッシュ復元だけでAIへ送信することはありません。「AI判定を中断」で進行中の判定を止められます。「AIを無効にする」で送信の同意を解除します。送信済みの本文は取り消せません。

## 5分以内の開き直しでは結果を再利用する

候補本文・返信確認結果・続きの取得位置・AI結果をローカルに5分保存します。期間・範囲・投稿者ごとに別々に保存し、開き直しても期限を延ばしません。⌘Rと返信成功後は取り直します。

画面を開いたときや検索条件を切り替えたときに、同じアカウントの期限切れ候補本文も削除します。Slack Hubを閉じている間は自動削除しません。

AI結果は同じ入力・モデル・判定文の版だけで再利用します。反映済みの結果を復元しても、送信への同意は引き継ぎません。SlackトークンやTypeSafeキーが変わった場合は以前の結果を使いません。Cacheは暗号化されないため、共有Macでは保存データの扱いにも注意してください。

## 履歴を確認できない場合

会話の種類に応じて、User Tokenに`im:history`・`channels:history`・`groups:history`・`mpim:history`が必要です。権限追加と再インストールの手順は[設定・トラブル対応](reference.md)を参照してください。

回数制限中は表示された待機期間の後に「続きを確認」を使います。AIの失敗でも候補は残り、「AIで並べる・再試行」で再度判定できます。TypeSafeの認証エラーでは後続の判定を止めます。キーを更新し、Slack Hubを開き直してから再試行してください。
